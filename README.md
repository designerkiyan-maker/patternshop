# بات فروش کانفیگ V2Ray

## ⚠️ نکته امنیتی مهم
توکن باتی که فرستادید همین‌جا در کد قرار داده شده (`config.py`). چون این توکن قبلاً در متن چت دیده شده،
**پیشنهاد می‌کنم از طریق @BotFather دستور `/revoke` را بزنید و یک توکن جدید بگیرید**، سپس توکن جدید را
داخل `config.py` جایگزین کنید. نگه‌داشتن `config.py` خارج از هرگونه ریپازیتوری عمومی (گیت‌هاب و ...) الزامی است.

## پیش‌نیازها
- Python نسخه 3.10 به بالا
- یک سرور یا سیستم با دسترسی دائمی به اینترنت (چون بات باید همیشه روشن بماند - پیشنهاد: یک VPS ساده)

## نصب

```bash
cd v2ray_bot
pip install -r requirements.txt
```

سپس فایل `.env.example` را کپی کن و توکن و آیدی خودت را داخلش بگذار:

```bash
cp .env.example .env
nano .env
```

و مقادیر را این‌طور تنظیم کن:
```
BOT_TOKEN=توکن_واقعی_بات
OWNER_ID=آیدی_عددی_تو
```

⚠️ فایل `.env` **هرگز** نباید وارد گیت‌هاب شود (در `.gitignore` قرار دارد). فقط `.env.example` (بدون مقدار واقعی) وارد گیت می‌شود.

## اجرا

```bash
python main.py
```

اگر همه‌چیز درست باشد، بات بلافاصله روشن می‌شود و آماده دریافت پیام است.
دیتابیس به‌صورت خودکار (`bot_database.db`) در همان پوشه ساخته می‌شود؛ نیازی به نصب هیچ دیتابیس جداگانه‌ای نیست.

برای اجرای دائمی روی سرور (که با بستن ترمینال بات خاموش نشود)، از یکی از روش‌های زیر استفاده کنید:

```bash
# روش ساده با screen
screen -S v2raybot
python main.py
# سپس Ctrl+A و D برای خروج بدون بستن بات

# یا با nohup
nohup python main.py > bot.log 2>&1 &
```

بهترین روش برای پروداکشن، ساخت یک systemd service است تا در صورت ری‌استارت سرور هم بات خودش بالا بیاید؛
در صورت نیاز بگویید تا فایل سرویس آن را هم برایتان بسازم.

## ساختار پروژه

| فایل | توضیح |
|---|---|
| `config.py` | توکن بات، آیدی مالک، مسیر دیتابیس |
| `database.py` | تمام عملیات دیتابیس (SQLite) |
| `keyboards.py` | ساخت دکمه‌های شیشه‌ای و منوها |
| `states.py` | مراحل مکالمه (FSM) |
| `handlers_user.py` | منطق مربوط به کاربر عادی |
| `handlers_admin.py` | منطق پنل مدیریت |
| `main.py` | نقطه اجرای بات |

## قابلیت‌هایی که پیاده‌سازی شده

### برای کاربر
- 🛒 **خرید کانفیگ**: انتخاب دسته‌بندی → انتخاب محصول → مشاهده قیمت و موجودی → ارسال رسید کارت‌به‌کارت →
  پس از تایید ادمین، کانفیگ به‌صورت خودکار و **یکتا** (هر لینک فقط یک‌بار به یک نفر) ارسال می‌شود.
- 🧪 **کانفیگ تست رایگان**: از یک مخزن کاملاً جدا از کانفیگ‌های فروشی. هر کاربر فقط یک‌بار می‌تواند دریافت کند
  (قابل تغییر در `config.py` با مقدار `MAX_TEST_PER_USER`). ادمین می‌تواند این قابلیت را کلاً خاموش/روشن کند.
- 📦 **سفارش‌های من**: مشاهده وضعیت سفارش‌ها (در انتظار / تایید شده / رد شده) و کانفیگ‌های دریافتی.
- 📞 **ارتباط با پشتیبانی**: پیام کاربر مستقیم برای همه ادمین‌ها ارسال می‌شود و ادمین با دکمه «پاسخ به کاربر»
  می‌تواند مستقیم از داخل بات جواب بدهد.

### برای ادمین
- 📂 مدیریت دسته‌بندی‌ها (افزودن، فعال/غیرفعال کردن، حذف)
- 📦 مدیریت محصولات داخل هر دسته‌بندی (نام، قیمت، توضیحات، فعال/غیرفعال، حذف)
- 🔗 افزودن لینک به بانک کانفیگ هر محصول (ارسال چند لینک هم‌زمان، هر خط یک لینک) — این‌ها لینک‌های فروشی هستند
  و به‌محض تخصیص به یک کاربر، دیگر به کس دیگری داده نمی‌شوند.
- 🧪 مدیریت مخزن کانفیگ تست (مخزن کاملاً جدا) + فعال/غیرفعال کردن کلی قابلیت تست
- 🧾 مشاهده و بررسی سفارش‌های در انتظار، تایید یا رد هر رسید با یک کلیک (کانفیگ به‌صورت خودکار از موجودی برداشته
  و برای کاربر فرستاده می‌شود؛ اگر موجودی تمام شده باشد ادمین هشدار می‌گیرد و باید ابتدا لینک اضافه کند)
- ✏️ ویرایش متن هر دکمه از منو (به‌همراه امکان گذاشتن ایموجی دلخواه)
- 💳 تنظیم شماره کارت و نام صاحب حساب برای پرداخت
- 📝 ویرایش پیام خوش‌آمدگویی ابتدای بات
- 👤 مدیریت چند ادمین (افزودن/حذف ادمین، مشاهده لیست)
- 📢 ارسال پیام همگانی به همه کاربران
- 📊 آمار فروش: تعداد کاربران، سفارش‌های در انتظار/تایید/رد شده، مجموع درآمد

### درباره‌ی «رنگ دکمه‌ها»
از تاریخ ۹ فوریه ۲۰۲۶ (Bot API 9.4)، تلگرام قابلیت رنگ‌آمیزی دکمه‌ها را اضافه کرده (فیلد `style`) و این پروژه
از همان استفاده می‌کند. برای هرکدام از دکمه‌های منو می‌توانید از پنل مدیریت → «✏️ ویرایش متن دکمه‌ها» →
«🎨 تغییر رنگ» یکی از رنگ‌های زیر را انتخاب کنید:
- 🔵 آبی (`primary`)
- 🟢 سبز (`success`)
- 🔴 قرمز (`danger`)
- ⚪️ پیش‌فرض/خاکستری (بدون تغییر)

⚠️ نکته: چون این ویژگی بسیار جدید است، **باید حتماً `aiogram` نسخه ۳.۲۰ یا بالاتر نصب باشد** (در `requirements.txt`
تنظیم شده) و همچنین اپلیکیشن تلگرام کاربر باید به‌روز باشد؛ در نسخه‌های خیلی قدیمی تلگرام ممکن است دکمه‌ها با
رنگ پیش‌فرض (خاکستری) نمایش داده شوند حتی اگر رنگ را تنظیم کرده باشید.

توجه: تغییر رنگ در پنل مدیریت بلافاصله ذخیره می‌شود، ولی چون Reply Keyboard فقط زمانی که پیام جدیدی همراه با
کیبورد جدید فرستاده شود رفرش می‌گردد، کاربر رنگ جدید را از پیام بعدی بات (مثلاً بعد از /start مجدد) می‌بیند.

### 👛 کیف پول
- کاربر از همان بخش «🤝 زیرمجموعه‌گیری من»، موجودی کیف پولش را می‌بیند و دکمه‌ی «➕ شارژ کیف پول» را می‌زند
- مبلغ دلخواه را وارد می‌کند، رسید کارت‌به‌کارت را می‌فرستد، و بعد از تایید ادمین (از پنل مدیریت →
  «👛 درخواست‌های شارژ کیف پول» یا مستقیم از پیام فوروارد‌شده)، مبلغ به کیف پولش اضافه می‌شود
- این موجودی (چه از شارژ دستی، چه از پورسانت زیرمجموعه‌گیری) در هر خرید بعدی **خودکار** کسر می‌شود
- اگر موجودی کیف پول کل قیمت محصول را پوشش دهد، نیازی به ارسال رسید خرید نیست و سفارش مستقیم برای
  تایید نهایی ادمین می‌رود

## قابلیت‌های جدید: زیرمجموعه‌گیری و کد تخفیف

### 🤝 زیرمجموعه‌گیری (رفرال)
- هر کاربر یک لینک اختصاصی دارد: `https://t.me/USERNAME_BOT?start=ref<آیدی_عددی_کاربر>`
- با دکمه‌ی «🤝 زیرمجموعه‌گیری من» قابل مشاهده است (لینک، تعداد زیرمجموعه، موجودی کیف پول)
- وقتی زیرمجموعه‌ی یک کاربر **اولین خرید تاییدشده‌اش** را انجام دهد، درصدی از مبلغ (پیش‌فرض ۱۰٪،
  قابل تغییر از پنل مدیریت → «🤝 تنظیمات زیرمجموعه‌گیری») به‌عنوان اعتبار کیف پول به دعوت‌کننده تعلق می‌گیرد
- این اعتبار به‌صورت **خودکار** در خرید بعدیِ خودِ کاربر کسر می‌شود (نیازی به کد یا اقدام دستی نیست)
- از پنل مدیریت می‌توان کل سیستم را فعال/غیرفعال کرد یا درصد پورسانت را تغییر داد

### 🎟 کد تخفیف
- از پنل مدیریت → «🎟 مدیریت کدهای تخفیف» → «➕ ساخت کد تخفیف جدید»
- دو نوع تخفیف پشتیبانی می‌شود: درصدی (`percent 20`) یا مبلغ ثابت (`fixed 50000`)
- می‌توان سقف تعداد استفاده تعیین کرد (0 = نامحدود)
- کاربر هنگام خرید، قبل از زدن «ادامه و ارسال رسید»، دکمه‌ی «🎟 وارد کردن کد تخفیف» را می‌زند و کد را تایپ می‌کند
- کد تخفیف و اعتبار کیف پول با هم قابل جمع هستند (هر دو روی یک خرید اعمال می‌شوند)
- اگر مبلغ نهایی صفر شود (کاملاً پوشش داده شده)، دیگر نیازی به ارسال رسید نیست و سفارش مستقیم برای تایید
  نهایی ادمین ارسال می‌شود
- اگر سفارشی رد شود، کیف پول مصرف‌شده و سهمیه‌ی کد تخفیف به‌طور خودکار برمی‌گردد

⚠️ نکته فنی: اگر دیتابیس (`bot_database.db`) از قبل روی سرورتان وجود دارد، نیازی به هیچ کاری نیست — با اجرای
مجدد بات، ستون‌های جدید به‌طور خودکار و بدون از‌دست‌رفتن داده‌های قبلی به دیتابیس اضافه می‌شوند (migration خودکار).

## پیشنهادهایی برای توسعه در آینده (در صورت تمایل اضافه می‌کنم)
- درگاه پرداخت آنلاین (زرین‌پال و مشابه) به‌جای کارت‌به‌کارت دستی
- کیف پول داخلی برای کاربران (شارژ حساب و خرید با موجودی)
- تخفیف و کد تخفیف
- ارسال خودکار یادآوری قبل از انقضای کانفیگ (در صورت اتصال به پنل مرزبان/سنایی)
- گزارش‌گیری اکسل از فروش
- پشتیبان‌گیری خودکار از دیتابیس

اگر هرکدام از این‌ها یا هر قابلیت دیگری مدنظرتان بود بگویید تا اضافه‌اش کنم.

## راه‌اندازی گیت‌هاب (برای بک‌آپ و آپدیت‌های آینده)

⚠️ **مخزن این پروژه Public (عمومی) است.** یعنی هرکسی می‌تواند کد را ببیند. قبل از هر push، همیشه مطمئن شو
که `.env` و `bot_database.db` هیچ‌وقت داخل کامیت‌ها نباشند (این دو در `.gitignore` قرار دارند و به‌صورت
خودکار نادیده گرفته می‌شوند، اما اگر یک بار قبل از اضافه‌کردن `.gitignore` کامیت شده باشند، باید تاریخچه
پاک‌سازی شود). هیچ توکن یا رمزی را مستقیم داخل کد ننویس؛ همیشه در `.env` بماند.

### مرحله ۱: ساخت مخزن روی گیت‌هاب
1. وارد github.com شو (اگر اکانت نداری، بساز)
2. روی "New repository" بزن
3. یک اسم بگذار (مثلاً `v2ray-bot`)
4. گزینه **Public** را انتخاب کن
5. دکمه Create repository را بزن

### مرحله ۲: نصب git روی سرور و اتصال به مخزن
```bash
# نصب git (اگر نصب نیست)
sudo apt update && sudo apt install -y git

cd ~/v2ray_bot

# معرفی خودت به git (فقط یک‌بار لازم است)
git config --global user.name "اسم خودت"
git config --global user.email "ایمیلت"

# مقداردهی اولیه مخزن
git init
git add .
git commit -m "نسخه اولیه بات"
git branch -M main

# اتصال به مخزن گیت‌هاب (آدرس را از صفحه ریپازیتوری خودت کپی کن)
git remote add origin https://github.com/USERNAME/v2ray-bot.git
git push -u origin main
```

چون مخزن Public است، برای `git push` فقط لاگین اکانت گیت‌هابت کافیست (نیازی به Personal Access Token نیست،
مگر گیت‌هاب خودش موقع push درخواست احراز هویت کند که در آن صورت طبق راهنمای خودش عمل کن).

### مرحله ۳: آپدیت‌های بعدی
هر وقت من فایل جدیدی برایت فرستادم:
1. محتوای فایل‌های تغییریافته را جایگزین کن (با `nano` یا آپلود مستقیم)
2. سپس:
```bash
cd ~/v2ray_bot
git add .
git commit -m "توضیح کوتاه از تغییر"
git push
sudo systemctl restart v2raybot
```

با این کار هم بک‌آپ کاملی از تمام نسخه‌های قبلی روی گیت‌هاب داری، هم اگر یک آپدیت مشکل داشت، به‌راحتی با
`git log` و `git checkout` می‌توانی به نسخه‌ی قبلی برگردی.

⚠️ یادآوری: چون `.env` و `bot_database.db` در `.gitignore` هستند، هیچ‌وقت وارد گیت‌هاب نمی‌شوند و در نتیجه
با هر `git pull` روی سرور دیگر هم دست‌نخورده باقی می‌مانند (باید دستی و یک‌بار روی هر سرور جدید ساخته شوند).

## نصب/آپدیت با یک خط دستور (curl | bash)

بعد از اینکه پروژه را روی گیت‌هاب گذاشتی، فایل `install.sh` را باز کن و خط زیر را با آدرس مخزن خودت
جایگزین کن:

```bash
REPO_URL="https://github.com/USERNAME/v2ray-bot.git"
```

سپس commit و push کن. از این به بعد، هم برای **نصب اولیه روی یک سرور جدید** و هم برای **آپدیت روی همین سرور**،
فقط کافیست این یک خط را بزنی — چون مخزن Public است، لینک raw مستقیم و بدون نیاز به هیچ توکنی کار می‌کند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/USERNAME/v2ray-bot/main/install.sh)
```

این اسکریپت به‌صورت خودکار:
- git, python3, pip, venv را در صورت نیاز نصب می‌کند
- اگر پروژه از قبل نصب باشد، فقط `git pull` می‌زند؛ اگر نباشد، کل پروژه را کلون می‌کند
- محیط مجازی پایتون و پکیج‌ها را می‌سازد/آپدیت می‌کند
- **فقط بار اول** از تو توکن بات و آیدی ادمین را می‌پرسد و `.env` را می‌سازد (دفعات بعد دست‌نخورده می‌ماند)
- یک سرویس `systemd` به اسم `v2raybot` می‌سازد تا بات همیشه در پس‌زمینه اجرا بماند و بعد از ری‌بوت سرور هم
  خودش دوباره بالا بیاید
- بات را (ری)استارت می‌کند

### آپدیت‌های بعدی (بعد از نصب اولیه)
از این به بعد برای هر آپدیت روی همین سرور، ساده‌ترین راه اجرای `update.sh` است (که کنار پروژه قرار دارد):
```bash
cd ~/v2ray_bot
./update.sh "توضیح تغییر"
```
یا اگر ترجیح می‌دهی همیشه از همان روش یک‌خطی استفاده کنی، دوباره همان دستور `bash install.sh` (یا نسخه curl آن)
را بزن — چون idempotent است و خودش تشخیص می‌دهد که فقط باید آپدیت کند.

## پنل مدیریت متنی حرفه‌ای (manage.sh)

برای مدیریت راحت‌تر بات از طریق یک منوی رنگی و شماره‌دار (شبیه ابزارهای معروف مثل مرزبان یا reality-ez)،
فایل `manage.sh` اضافه شده. کافیست خط `REPO_URL` داخلش را مثل `install.sh` با آدرس مخزن خودت جایگزین کنی،
سپس commit و push کنی.

### اجرا (بعد از نصب)
```bash
bash ~/v2ray_bot/manage.sh
```

### اجرای مستقیم روی یک سرور تازه (بدون نصب قبلی)
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/USERNAME/v2ray-bot/main/manage.sh)
```

[8] مشاهده آمار فروش              — مستقیم از دیتابیس، بدون نیاز به تلگرام
[9] تغییر توکن یا آیدی ادمین       — بدون نیاز به دست‌کاری دستی فایل .env
